## 二、建议顺序（附理由）

| # | 模块 | 学什么 | 为什么现在学 | 与项目的关系 |
|---|---|---|---|---|
| **S1** | **时钟树与复位** | HSI/HSE/PLL → 72MHz；AHB / APB1 / APB2 分频；**APB1 分频≠1 时定时器时钟 ×2**；外设时钟门控；`SystemInit` 干了什么 | ★ 你反复踩"忘开时钟""频率算错"，根全在这 | 直接决定 `f_cnt` 怎么算 |

| 之后 | USART 调试串口 | `printf` 重定向、命令解析、环形缓冲 | 调试效率翻倍（`labs/Lab6` 已有，随时可回来做） | 参数下发（项目 M3/M4） |
| 之后 | ADC + DMA | 规则/注入通道、定时器触发采样、DMA 搬运 | 回波采集 | 项目后续 |
| 之后 | TIM1 互补输出 / 死区 | 高级定时器、`CHxN`、死区、刹车 | 若将来直接驱半桥 | 驱动级相关 |
| 最后 | 看门狗 / 低功耗 / 启动流程 | IWDG/WWDG、Stop/Standby、启动文件与 map | 从"能跑"到"能交付" | 工程化 |

## 三、本阶段目标（做完 S1–S4 你应该能）

1. 看到任何一个外设，能自己说出"它的时钟在哪条总线、怎么开、实际频率多少"
2. 能解释"为什么我的 ISR 会晚 0.3µs"，并知道怎么减
3. 能用 STM32 反过来**测量**自己产生的信号（不再只靠示波器肉眼比划）
4. 有干净的 `delay_us/delay_ms`，能用按键控制系统的行为

---

## 四、怎么学（建议）

- **一个模块一个工程**：沿用现成的 `1014_blinky` 工程，把对应 `.c` 替进去编译下载
- **先猜后验**：每个任务都先自己在纸上算出结果，再下载看对不对（错了才有收获）
- **用示波器/逻辑分析仪当裁判**：S1/S2 的很多结论只能靠测量确认
- **每完成一个模块，把"我原来以为是 X，实际是 Y"写进 README 末尾**——这些才是真收获
