# Lab 4 — 四通道"边沿表"：复现论文图 6 ★ 技术核心 ★

## 目标

用 TIM2 的 4 个通道，在 PA0–PA3 上产生 **SYNC / OE / PULSE / DAMP** 四路时序，与论文图 6 一致。

## 目标波形（图 6，一个"发射组" = 16 节拍）

> "节拍"是图 6 自带的时钟单位（1 节拍 = Sys_clk 半周期）。
> 换算到本工程标准定时器（f_cnt = 72 MHz）：**1 节拍 = 18 tick，一个周期 = 288 tick**。

```
             ← 16 节拍（1 个周期 = 288 tick）────────────→
        节拍=0        节拍=4   节拍=8               节拍=16
OE     ─╱‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾‾╲______________________
PULSE  ─╱‾‾‾‾‾‾‾‾‾‾‾╲__________________________________
DAMP   ──────────────╱‾‾‾‾‾‾‾‾‾‾‾╲______________________
                        ↑
              PULSE↓ 与 DAMP↑ 在同一时刻（图 6 里同一条虚线）
```

| 时刻（节拍 / tick） | 动作 |
|---|---|
| 0 / 0 | **OE↑ 与 PULSE↑ 同时** |
| 4 / 72 | **PULSE↓ 与 DAMP↑ 同时** |
| 8 / 144 | **OE↓ 与 DAMP↓ 同时** |
| 16 / 288 | 回到 0，下一组 |
| −1 / 270 | Trigger(SYNC)↑，图 6 中拉高后保持 |

| 信号 | 高电平宽度 | 占空比 |
|---|---|---|
| OE | 8 节拍 = 144 tick | 50% |
| PULSE | 4 节拍 = 72 tick | 25% |
| DAMP | 4 节拍 = 72 tick | 25% |

> ⚠ **OE 只高"半"个周期**（节拍 0~8）；节拍 8~16 的 OE 低电平，就是两次发射之间
> 的间隔（图 6 用等长示意，真实间隔长度由 Lab 5 控制）。

## ★ 本工程标准参数（Lab4–6 统一采用）

| 量 | 取值 |
|---|---|
| f_cnt（定时器计数频率） | **72 MHz**（PSC = **0**，不分频） |
| 1 tick | **13.9 ns** |
| ARR | **287**（288 tick） |
| 周期 | **4 µs** |
| 激励频率 | **250 kHz** |
| 边沿（tick） | OE↑/PULSE↑ = 0；PULSE↓/DAMP↑ = 72；OE↓/DAMP↓ = 144；SYNC = 270 |
| 脉冲宽度 | OE 高 2 µs；PULSE / DAMP 高 1 µs |

> **改频率 = 保持 f_cnt，按比例改 ARR 与各 CCR**（详见 Lab 6）。
> 为什么选 72 MHz 而不是更"整齐"的低频：Lab 6 要覆盖 50–300 kHz，
> 低计数频率下 150k / 300k 除不尽，会有明显误差。

## 本 Lab 的灵魂：这是个设计题，不是填空题

**难点一**：一个通道 Toggle 一圈只翻一次，但 OE 在一个组内要"先升后降"两次。
**难点二**：**DAMP 的高电平夹在周期正中间（tick 72~144）**，既不贴起点也不贴终点。

### 路线 A：硬件 PWM —— 但有个"死穴"

每个通道用 PWM 输出一段高电平：

| 通道 | 目标高电平区间（tick） | 能直接用 PWM 吗 |
|---|---|---|
| OE | 0 – 144 | ✅ PWM 模式 1，CCR=144（窗口从起点开始） |
| PULSE | 0 – 72 | ✅ PWM 模式 1，CCR=72（窗口从起点开始） |
| DAMP | 72 – 144 | ❌ **中间窗口，单个定时器做不出** |

**为什么 DAMP 做不出？** 一个定时器只有一条 CNT，PWM 窗口只能贴在周期两端：

```
PWM1 → 窗口 = [0, CCR)          （贴着起点）
PWM2 → 窗口 = [CCR, ARR+1)      （贴着终点）
```

DAMP = [72,144) 是**正中间**的一段，PWM1/PWM2 都够不着。**这就是路线 A 的真正难点。**

两条出路：
1. **把定时器周期设成"组宽"(144 tick)**，DAMP 就成了组内"结尾窗口" [CCR,144)，PWM2 成立；
   组与组的间隙再用第二个定时器或中断产生。
2. **直接走路线 B**（推荐先用它跑通）。

### 路线 B：定时器中断 + 手动翻转 GPIO

定时器按固定间隔中断，在 ISR 里按 `EDGE_TABLE` 翻引脚。**任意时刻都能翻，无中间窗口问题。**

- 优点：直观、能精确表达图 6 的每一个边沿，是理解时序本质的好方法
- 代价：精度受中断延迟与 ISR 执行时间影响，需用示波器评估

> 建议：**先用路线 B 把时序跑出来、彻底理解**，再挑战路线 A 拿精度。

## 换算助手

标准参数（f_cnt = 72 MHz，一个**完整周期 = 288 tick = 4 µs**）：

| 目标 | tick | 说明 |
|---|---|---|
| OE 高（半周期） | 144 | tick 0 → 144 |
| PULSE 高（1/4 周期） | 72 | tick 0 → 72 |
| DAMP 高（1/4 周期） | 72 | tick 72 → 144 |
| SYNC 提前量 | 18 | 1 节拍（0.25 µs） |

> 换算口诀：**tick = 时间(µs) × 72**（f_cnt = 72 MHz → 1 µs = 72 tick）。
> 于是 250 kHz 一个周期 4 µs = 288 tick → **ARR = 287**；2 µs = 144 tick。

| 激励频率 | 周期 | ARR（f_cnt=72MHz） | 边沿 tick（1/4, 1/2） |
|---|---|---|---|
| 50 kHz | 20 µs | 1439 | 360, 720 |
| 100 kHz | 10 µs | 719 | 180, 360 |
| 150 kHz | 6.67 µs | 479 | 120, 240 |
| 200 kHz | 5 µs | 359 | 90, 180 |
| **250 kHz** | **4 µs** | **287** | **72, 144** |
| 300 kHz | 3.33 µs | 239 | 60, 120 |

## 常见坑

- **把"组"和"周期"搞混** → OE 只高半周期，若让定时器周期 = 组宽，OE 会变成常高
- **忽略 DAMP 是中间窗口** → 死磕单定时器 PWM 也做不出，白费功夫（见路线 A 死穴）
- **PWM1/PWM2 选错** → 该高的地方低、该低的地方高（波形上下翻转就检查这个）
- **CCMR1/CCMR2 搞混** → ch1/ch2 在 CCMR1，ch3/ch4 在 CCMR2
- **CCR 值超过 ARR** → 该边沿永不发生
- **路线 B 里忘了清中断标志** → 中断反复触发，程序卡死
