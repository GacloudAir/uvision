# Lab 5 — 中断与"发射间隔"

## 目标

让 Lab4 的发射组（**288 tick = 4 µs**）**每隔一段间隔**重复一次（示例 ≈ 0.7 ms），
并在间隔里预留"做其他事"的空间。

## ★ 本工程标准参数（Lab4–6 统一）

| 量 | 取值 |
|---|---|
| f_cnt / PSC | 72 MHz / **0**（1 tick = 13.9 ns） |
| 一组（Lab4 的波形） | 288 tick = 4 µs（OE 高 144、PULSE 高 72、DAMP 高 72） |
| 发射间隔（本 Lab） | 示例 ≈ 50400 tick ≈ 0.7 ms（可调） |

## 前置知识

- 中断向量、NVIC 优先级——见 `docs/学习路线图.md` 模块 7
- TIM 更新事件与 UIF 标志

## 两种做法（先选，再写）

| | 做法 A：间隔吃进周期 | 做法 B：独立节拍定时器（中断） |
|---|---|---|
| 原理 | TIM2 周期设为"组+间隔"，高电平只占前 144 tick | TIM3 每 0.7 ms 中断一次，触发发射 |
| 中断 | 不需要 | 需要 |
| 精度 | 最高（纯硬件） | 高（受中断延迟影响） |
| 间隔里做别的事 | 不方便 | **方便** |
| 做全四路 | ⚠ **DAMP 是中间窗口，纯 PWM 做不出** | ✅ 没有这个限制 |
| 适合 | 单纯重复发射（能接受先做 3 路） | 后续要接回波采集/参数更新 |

> 建议：先按 **做法 A** 跑通、看到间隔（OE/PULSE 够用），再按 **做法 B** 把四路做全，
> 体会两者差别。

## 换算助手

| 目标 | 总 tick（f_cnt = 72 MHz） | 分解 |
|---|---|---|
| 0.7 ms = 700 µs | 50400 | PSC=0，**ARR = 50400 − 1 = 50399**（≤65535 ✓） |
| 更长的间隔 | 见公式 | 间隔(µs) × 72 = tick 数；ARR = tick − 1 |

**0x8B99** = 35737（十进制）。结合你选的计数频率，换算它对应的时间——这是论文里给出的发射间隔计数值。

## 验证方法

| 验证点 | 方法 | 期望 |
|---|---|---|
| 发射间隔 | 示波器，触发 OE | 相邻发射组间隔约 0.7ms |
| 中断频率 | Keil 调试看标志变化 / 翻转测试引脚 | 约 1.43kHz |
| 清标志 | 单步调试 | UIF 被正确清零，不反复中断 |

## 常见坑

- **忘记清 UIF** → 中断连续触发，程序"死"在中断里
- **NVIC 忘了使能** → 中断函数根本不会被调用
- **中断函数名写错**（如写成 `TIM3_IRQhandler`） → 链接不到，或进了别的默认处理
- **ISR 里做事太多** → 占用时间过长，影响时序

## 关键领悟

> 中断把"时间到了"这件事交给硬件来提醒 CPU。
> 但**精确的波形仍然交给定时器硬件**，中断只负责"调度"与"善后"。
> 这就是嵌入式里"让硬件干硬件的活、CPU 干决策的活"的分工哲学。
